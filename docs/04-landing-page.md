# 04. 랜딩페이지 스펙

경로: `/` (marketing 라우트 그룹, 비로그인 사용자 기본 진입점)

## 1. 정보 구조 (섹션 순서)

1. **Hero**
2. **Problem** (현재 얼마나 느린가)
3. **Parcel Intelligence** (7개 인텔리전스 모듈)
4. **Data Provenance** (20+ 원천과 출처·기준일·신뢰도)
5. **Feasibility / 할 수 있는 것 vs 없는 것** (기대치 관리)
6. **Segment별 활용 시나리오** (건축주 / 건축사사무소 / 부동산플랫폼)
7. **요금제(Pricing)**
8. **FAQ**
9. **CTA (구글로 시작하기)**
10. **Footer**

## 2. 섹션별 카피 및 구성

### 2.1 Hero
- 브랜드 가제: `PLINT` (Parcel Intelligence)
- 헤드라인: "땅의 가능성을 보이게 만들다."
- 서브헤드: "주소 하나로 필지, 법규, 시장, 위험 데이터를 결합하고 실제 설계로 이어지는 3D 개발 시나리오를 만듭니다"
- 핵심 지표 강조: "기존 4~24시간 → 10분"
- CTA 버튼: "구글로 무료 시작하기" (클릭 시 `/login`)
- 우측/하단: 실제 매스모델 3D 렌더 이미지 또는 대시보드 스크린샷 목업 (초기엔 정적 이미지 placeholder)

### 2.2 Problem
`00-business-plan.md`의 "Problem" 섹션 내용을 재구성:
- 건축주가 겪는 프로세스를 체크리스트 형태로 나열 (지적도 확인 → 토지이용계획원 → 건축물대장 → 건폐율/용적률 → 일조권 → 주변현황 → 매스스케치)
- Before/After 비교 카드: "수작업 4~24시간" vs "자동화 10분"
- "소규모 사무소일수록, 상담비 50~100만원 부담" 인용구 형태로 강조

### 2.3 Parcel Intelligence
Identity, Planning, Context, Market, Risk, Scenario, Decision Pack의 7개 모듈을 사용자의 의사결정 흐름으로 시각화한다. 내부 API 수보다 사용자가 얻게 되는 판단과 산출물을 우선한다.

| Phase | 제목 | 한줄 설명 | 소요시간 |
|---|---|---|---|
| 1 | 대지 정보 자동 수집 | 11개 공공API 병렬 조회로 필지·용도지역·현황 통합 | ~5초 |
| 2 | 법규 자동 검토 | 건폐율·용적률·높이·일조권·주차대수 산출 | ~2초 |
| 3 | 3D 매스모델 자동 생성 | SketchUp MCP로 법규 엔벨로프 반영 매스 생성 | ~3분 |
| 4 | 사업성 분석 리포트 | 예상 수익·총사업비·수익률 자동 산출 | ~1초 |

### 2.4 Data Sources
- "20개 이상의 데이터 원천을 필지 하나로 연결합니다" 문구와 원천·기준일·신뢰도 샘플을 보여준다. 모든 원천이 실시간이라는 표현은 사용하지 않는다.
- 신뢰성 강조용 섹션이므로 텍스트는 최소화, 시각적 나열 위주

### 2.5 할 수 있는 것 / 할 수 없는 것
`00-business-plan.md`의 "Scope" 섹션 반영. 2열 비교(체크 아이콘 vs X 아이콘) + 하단에 포지셔닝 문구를 인용구로 강조:
> "설계의 첫 10%를 자동화합니다. 건축사의 전문적 판단을 대체하는 것이 아니라, 판단을 위한 기초 자료를 빠르게 마련해주는 도구입니다."

이 섹션은 과장 방지를 위해 반드시 포함한다 (기대치 관리 목적).

### 2.6 Segment별 시나리오
탭 또는 3열 카드: 건축주·디벨로퍼 / 건축사사무소 / 부동산·투자플랫폼. 각각 "이런 분께" + "이렇게 활용하세요" 짧은 설명.

### 2.7 요금제
`plans` 테이블 데이터를 서버 컴포넌트에서 조회해 렌더링 (하드코딩 금지, DB 기준 단일 소스). 플랜별: 이름/가격/월 크레딧/주요 기능 bullet/CTA버튼.
비교 참고용 카피: "건축사 상담비 50~100만원 대신, 월 구독으로 무제한에 가깝게" (Segment A 대상).

### 2.8 FAQ
`faqs` 테이블에서 `is_published=true`인 항목을 카테고리별 아코디언으로 렌더링.

### 2.9 CTA + Footer
- 최종 CTA: "지금 첫 지번을 분석해보세요" + 구글 로그인 버튼
- Footer: 서비스 소개 한줄, 이용약관/개인정보처리방침 링크, 사업자정보(추후 기입), 문의 이메일

## 3. 반응형/성능 원칙

- 랜딩페이지는 정적 생성 또는 캐시 가능한 서버 렌더링을 사용한다.
- 모바일 우선 반응형, Hero/Solution 섹션은 모바일에서 세로 스택
- Hero의 3D는 Three.js로 구현하되 저사양/접근성 환경을 위한 정적 폴백을 둔다.

## 4. 디자인 톤

- 건축/부동산 도메인 특성상 "신뢰감 있고 전문적인" 톤. 과도한 화려함보다 정확한 데이터/수치 노출을 우선.
- 상세 디자인 토큰(색상/타이포)은 프론트엔드 구현 시 `frontend-design` 가이드 원칙을 따라 구체적으로 정할 것 (이 문서는 정보구조/카피 중심).

## 5. 결정 필요 항목

- 실제 서비스명/로고/브랜드 컬러 (현재 미정 — 가제 "지번AI" 등으로 임시 진행 가능)
- 요금제 최종 가격(기획안의 월 10~30만원/20~50만원/건당 1,000~5,000원은 초안 수치이므로 `plans` 테이블 seed 시 확정 필요)
