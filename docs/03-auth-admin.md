# 03. 인증 & 어드민 페이지 스펙

## 1. 인증 — 구글 로그인

### 1.1 방식
Supabase Auth의 Google Provider를 사용한다. 자체 OAuth 클라이언트 구현 없이 Supabase 대시보드에서 Google Cloud Console 클라이언트 ID/Secret을 등록해 연결한다.

### 1.2 화면
- `/login` — "Google로 계속하기" 버튼 하나만 있는 미니멀한 화면 (로고 + 버튼 + 이용약관/개인정보처리방침 링크)
- 로그인은 구글만 지원. 이메일/비밀번호 로그인은 이번 스펙에서 제외.
- 로그인 성공 시 최초 방문자는 `/onboarding`(간단한 소속 구분: 건축주/건축사/부동산플랫폼 선택, `users.segment`에 저장)으로, 기존 사용자는 `/dashboard`로 이동.
- `/` 랜딩페이지는 항상 공개 상태로 유지하며, 로그인 여부에 따라 자동 리다이렉트하지 않는다. 로그인은 네비게이션의 `Google 로그인` 버튼에서만 시작한다.
- 운영 배포 전 Supabase Dashboard의 Google Provider와 Google Cloud OAuth 동의 화면을 설정하고, Redirect URL로 `https://<supabase-project-ref>.supabase.co/auth/v1/callback` 및 서비스의 `/auth/callback`을 등록한다.

### 1.3 세션/요청 프록시
- 현행 `@supabase/ssr`의 브라우저/서버 클라이언트를 분리하고 요청 프록시에서 `getClaims()`로 토큰을 갱신한다.
- `(dashboard)`, `(admin)` 경로 그룹 접근 시 서버에서 세션을 확인하고 없으면 `/login`으로 리다이렉트한다.
- `(admin)` 그룹은 세션 확인 후 추가로 `users.role === 'admin'` 확인, 아니면 `/dashboard`로 리다이렉트 (403 대신 조용히 돌려보냄)

### 1.4 권한 모델
- `user`: 기본값. 본인 분석/구독/결제만 조회 가능
- `admin`: 전체 사용자/구독/결제/사용량/콘텐츠 관리 가능. 권한은 사용자가 수정할 수 없는 `app_metadata` 또는 서버 관리 DB 값만 사용한다. `user_metadata`는 권한 판정에 사용하지 않는다.

## 2. 어드민 페이지 (`/admin/*`)

좌측 사이드바 + 우측 컨텐츠 레이아웃. 사이드바 메뉴 구성:

1. 대시보드 (개요)
2. 사용자 관리
3. 구독/결제 관리
4. API 사용량 모니터링
5. 콘텐츠 관리 (공지사항 / FAQ)
6. 설정

### 2.1 `/admin` — 개요 대시보드
- 오늘/이번주/이번달 신규 가입자 수
- 활성 구독자 수, 플랜별 분포 (도넛 차트)
- 이번달 매출 합계 (결제 성공 기준)
- 오늘 분석 요청 건수, 성공/실패율
- 외부 API 헬스체크 상태 요약 (provider별 정상/장애 뱃지 — `api_provider_status` 테이블 기반)
- 최근 실패한 분석 5건 리스트 (바로가기 포함)

### 2.2 `/admin/users` — 사용자 관리
- 테이블: 이름/이메일/가입일/소속구분(segment)/현재 플랜/상태/최근 로그인
- 검색(이메일), 필터(플랜별, 가입일 범위)
- 사용자 상세 클릭 시: 프로필 정보 + 구독 이력 + 결제 이력 + 분석 이력 요약을 한 화면에서 조회 (읽기 전용, 최초 버전에서는 직접 수정 기능 없음. 필요 시 Supabase 대시보드 직접 사용)

### 2.3 `/admin/billing` — 구독/결제 관리
- 구독 현황 테이블: 사용자/플랜/상태/다음 결제일/잔여크레딧
- 결제 내역 테이블: 결제일/사용자/금액/상태/포트원 결제ID
- 상태 필터(활성/해지예정/연체/취소), 기간 필터
- 실패 결제 재시도는 최초 버전 범위 밖 (포트원 자체 재시도 정책에 위임, 추후 필요 시 추가)
- 상세 스펙은 `06-payment-billing.md` 참조

### 2.4 `/admin/usage` — API 사용량 모니터링
- provider별 최근 24시간/7일/30일 호출 수, 평균 응답시간, 에러율 (라인차트 + 테이블)
- provider별 추정 비용 합계 (기간 선택 가능)
- 최근 에러 로그 리스트 (provider/endpoint/status_code/시각)
- `api_provider_status` 기반 실시간 헬스 배지

### 2.5 `/admin/content` — 콘텐츠 관리
탭 2개: 공지사항 / FAQ

**공지사항**
- 목록(제목/작성일/게시상태), 신규작성/수정/삭제
- 마크다운 에디터(간단한 textarea + 미리보기 정도로 충분, 별도 WYSIWYG 라이브러리 도입은 선택사항)
- 게시/비공개 토글

**FAQ**
- 카테고리별 목록, 신규작성/수정/삭제, 순서 변경(display_order), 게시/비공개 토글

### 2.6 `/admin/settings`
- 최초 버전에서는 플레이스홀더 수준으로 구현 (예: 플랜 가격 조회만, 수정은 추후)
- 향후 요금제(plans 테이블) 수정 UI, provider 단가 설정 등을 이곳에 확장

## 3. 컴포넌트 재사용 원칙

- 대시보드/어드민 공통으로 쓰는 데이터 테이블은 shadcn/ui의 `DataTable` 패턴(TanStack Table 기반)을 하나 만들어 재사용
- 차트는 `recharts` 사용

## 4. 결정 필요 항목

- 관리자 계정을 몇 명이나 둘지, 최초 관리자 계정(어떤 구글 이메일)을 어떻게 지정할지 — seed 스크립트로 특정 이메일에 role='admin' 부여하는 방식 제안, 실제 이메일 주소는 착수 전 확인 필요
