# 08. 공공 API 전수검토 및 제품 확장 설계

> 조사 기준일: 2026-09-03  
> 목적: 기존 11개 데이터 항목의 실제 구현 가능성을 확인하고, 이를 하나의 `Parcel Intelligence` 제품으로 재설계한다.

## 1. 결론

이 아이디어는 판매 가능한 상품으로 만들 수 있다. 다만 경쟁력은 "11개 API를 연결했다"가 아니라, 흩어진 원천 데이터를 한 필지 기준으로 정규화하고 아래 질문에 한 번에 답하는 데서 생긴다.

1. 이 필지는 무엇인가?
2. 무엇을 어느 정도 지을 수 있는가?
3. 주변은 어떤 시장과 생활권인가?
4. 개발을 막거나 비용을 키울 위험은 무엇인가?
5. 어떤 대안이 수익성과 공간 품질을 동시에 높이는가?
6. 검토 결과를 바로 상담·투자심의·설계착수에 쓸 수 있는가?

따라서 제품의 정의는 다음이 적합하다.

> **주소 하나를 필지 단위의 데이터·법규·시장·위험·3D 시나리오로 변환하고, 의사결정 문서와 설계 파일까지 생성하는 개발검토 OS**

현재 명세의 방향은 맞지만 원천 API의 성격을 지나치게 단순화했다. 실제 구현에서는 다음을 바로잡아야 한다.

- 11개 항목은 11회의 단순 REST 호출이 아니다. REST, WMS/WFS, 대용량 파일 적재, 지도 타일, JavaScript 3D SDK가 섞여 있다.
- 변하지 않는 대용량 공간정보는 분석 요청 때마다 외부 호출하지 말고 PostGIS에 정기 적재한다.
- 공공 API의 원본값과 플랫폼이 계산한 추론값을 분리하고, 모든 결과에 출처·기준일·라이선스·신뢰도를 붙인다.
- VWorld 3D 화면을 원시 LOD 파일 공급원으로 가정하면 안 된다. 주변 건물은 건물 폴리곤과 건축물대장 높이 정보를 결합해 자체 LOD1으로 생성하는 방식이 안전하다.
- 실거래 API의 주소는 일부 마스킹되므로 "정확한 반경 내 비교사례"가 항상 가능한 것은 아니다. 행정구역·용도·면적·연식 기반의 유사사례 모델로 설계해야 한다.
- 결과는 인허가 확정판정이 아니라 근거가 추적되는 사전검토다. 대신 누락·불확실성을 숨기지 않는 것이 유료 제품의 신뢰가 된다.

## 2. 기존 명세 11개 항목 전수검토

### 2.1 필지 형상·면적

- **권장 원천:** [국토교통부 연속지적도형정보](https://www.data.go.kr/data/15056910/openapi.do), VWorld WFS
- **수집 방식:** PNU 또는 공간 BBOX로 WFS 조회, 대량 서비스는 시도별 SHP를 사전 적재
- **정규화 결과:** PNU, 지목, 공부면적, 필지 Polygon/MultiPolygon, 경계 길이, 형상 복잡도
- **파생 결과:** 유효 전면폭, 장단변, 세장비, 코너필지 여부, 인접필지 목록
- **판정:** 핵심 데이터로 사용 가능
- **주의:** 연속지적도 경계는 공간 분석용 참조자료이지 지적측량 성과나 법적 경계 확정자료가 아니다. 대용량 파일은 API 페이지와 이용조건이 다를 수 있으므로 배포·가공 허용 범위를 별도 확인한다.

### 2.2 용도지역·용도지구·구역

- **권장 원천:** [토지이용계획정보 전국 파일](https://www.data.go.kr/data/15045900/fileData.do), [VWorld WMS/WFS](https://www.data.go.kr/data/15058805/openapi.do?recommendDataYn=Y)
- **수집 방식:** 전국 파일 또는 공간레이어를 정기 적재한 뒤 필지와 공간 교차
- **정규화 결과:** 규제 코드, 명칭, 필지 내 중첩 면적/비율, 고시·근거 식별자
- **파생 결과:** 단일 규제가 아니라 `규제 매트릭스`와 충돌/우선순위
- **판정:** 사용 가능하나, 여기서 건폐율·용적률과 모든 행위제한이 완성되는 것은 아님
- **주의:** 국가공간정보포털의 구 API 다수는 2023-12-31 종료되었다. [폐기 공지](https://www.data.go.kr/bbs/ntc/selectNotice.do?originId=NOTICE_0000000003431)를 기준으로 VWorld/K-Geo 계열의 현행 서비스 ID를 사용해야 한다.

### 2.3 건축물 현황

- **권장 원천:** [건축HUB 건축물대장정보](https://www.data.go.kr/data/15134735/openapi.do)
- **수집 방식:** 시군구코드·법정동코드·본번·부번을 기준으로 총괄/표제부/층별/전유부를 조합
- **정규화 결과:** 주용도, 구조, 층수, 높이, 건축/연면적, 사용승인일, 주차, 세대/호, 부속건축물
- **파생 결과:** 현황 FAR/BCR, 노후도, 철거 검토 대상, 리모델링/증축 후보
- **판정:** 핵심 데이터로 사용 가능
- **명세 수정:** 공개 건축물대장 API에서 `소유자`를 받는다는 전제는 삭제한다. 개인 소유정보를 상품 데이터로 취급해서는 안 된다.
- **주의:** 건축HUB 전환으로 기존 건축데이터 PK가 변경되었으므로 자체 식별자와 원천 PK 이력을 함께 저장한다.

### 2.4 주변 건물 3D

- **확인 원천:** [VWorld WebGL 3D 지도 API](https://www.data.go.kr/data/3073144/openapi.do), [GIS건물통합정보](https://www.data.go.kr/data/15083092/fileData.do)
- **판정:** VWorld 3D API는 Cesium/WebGL 기반 시각화 SDK로는 유효하지만, 명세가 가정한 "LOD1~2 원시 모델 다운로드 → SketchUp 임포트" 계약은 공식 API 설명만으로 보장되지 않는다.
- **권장 구현:** GIS 건물 풋프린트 + 건축물대장 층수/높이를 결합해 서버에서 자체 LOD1 블록을 만든다. 높이 결측은 `층수 × 용도별 표준 층고`로 추정하고 추정 플래그를 남긴다.
- **산출:** Three.js용 instanced mesh, GLB, SketchUp 컨텍스트용 단순 건물군
- **제품 이점:** 외부 3D 원본 포맷과 다운로드 권한에 종속되지 않고 전국에서 동일한 방식으로 동작한다.

### 2.5 지형 표고·경사

- **확인 원천:** VWorld/국토지리정보원 DEM 계열, [토지특성정보 WMS/WFS/속성정보](https://www.data.go.kr/data/15123549/openapi.do), [DEM 메타데이터](https://www.data.go.kr/data/15067632/fileData.do)
- **판정:** `필지 하나 → VWorld DEM REST → 경사도`라는 단순 API 계약으로 확정하면 안 된다. DEM은 타일/파일 취득과 좌표계·해상도 처리가 필요한 공간 래스터다.
- **권장 구현:** 지역별 DEM 타일을 별도 취득·캐시해 필지 내부 표고표본, 평균/최소/최대고, 평균/최대경사, 절성토 개략량을 계산한다.
- **MVP 폴백:** 토지특성정보의 지형고저·형상 정보를 정성 등급으로 제공하고, DEM 미보유 지역은 정밀 경사 분석을 비활성화한다.

### 2.6 항공영상

- **권장 원천:** VWorld WMS/WMTS 항공영상
- **수집 방식:** 분석 화면의 배경지도와 리포트용 서버 스냅샷을 분리
- **정규화 결과:** 영상 촬영연도, 지도 범위, 해상도, 출처표시
- **판정:** 현황 이해와 프레젠테이션에 유용
- **주의:** "현장사진 대용"으로 표현하지 않는다. 촬영시점 차이, 가림, 옥상/입면 미확인 때문에 현장조사를 대체할 수 없다. 이미지 자체를 파일 산출물에 재배포할 때의 허용조건도 별도 확인한다.

### 2.7 도로·접도

- **권장 원천:** [도로중심선 WMS/WFS](https://www.data.go.kr/data/15056842/openapi.do), [도시계획 도로·시설 WMS/WFS](https://www.data.go.kr/data/15058180/openapi.do), 토지특성정보, 연속지적도
- **판정:** 도로중심선 하나만으로 건축법상 접도와 유효 도로폭을 확정할 수 없다.
- **권장 계산:** 필지 경계와 도로/구거/공공용지 필지의 접합, 도로중심선 등급, 토지특성의 도로접면, 도시계획시설을 함께 사용한다.
- **산출:** 현황도로/계획도로 구분, 추정 폭, 접한 길이, 2m 접도 후보, 코너가각 후보, 도로후퇴 검토 필요 플래그
- **UI:** `확정`, `공공데이터 기반 추정`, `도면 확인 필요`의 3단계 신뢰표시

### 2.8 개별공시지가

- **권장 원천:** VWorld의 개별공시지가 속성정보 또는 전국 개별공시지가 표준데이터
- **수집 방식:** PNU와 기준연도로 조회하고 이력을 내부 시계열로 축적
- **산출:** ㎡당 공시지가, 총 공시지가, 전년 대비 변동률, 실거래 대비 괴리
- **판정:** 사용 가능
- **주의:** 구 국가공간정보포털 엔드포인트는 폐기 대상이므로 현행 데이터셋 ID를 배포 전에 다시 고정한다. 공시지가는 감정가나 실제 매입가가 아니다.

### 2.9 실거래가

- **권장 원천:** [토지 매매 실거래](https://www.data.go.kr/data/15126466/openapi.do), [단독/다가구 매매](https://www.data.go.kr/data/15126465/openapi.do), 공동주택·연립다세대·오피스텔·상업업무용·전월세 API
- **수집 방식:** 법정동 앞 5자리 + 계약월로 유형별 API를 병렬 조회한 뒤 용도·면적·연식·입지로 재필터링
- **산출:** 유사사례 목록, 중앙값/사분위, ㎡당 가격, 기간 추이, 표본 수와 신뢰도
- **판정:** 사업성 분석의 핵심이나 단일 API로는 불충분
- **주의:** 토지 지번이 일부 마스킹되므로 모든 사례를 정확한 좌표로 변환할 수 없다. `반경 500m 실거래`처럼 과도하게 정밀한 문구 대신 `동일 생활권 유사사례`를 기본으로 한다.

### 2.10 일조·일사·기상

- **권장 원천:** [기상청 ASOS 일자료](https://www.data.go.kr/data/15059093/openapi.do), [기상청 단기예보](https://www.data.go.kr/data/15084084/openapi.do)
- **수집 방식:** 최근 관측치와 장기 평년성 데이터를 분리하고 가장 가까운 관측소/격자와 거리를 기록
- **산출:** 월별 일조·일사·풍향풍속 기후 프로필, 공사/운영 리스크 참고값
- **판정:** 기후 컨텍스트로 유효
- **주의:** 관측소·5km 격자 데이터는 필지별 미기후가 아니다. 법규 일조 검토와 그림자 시뮬레이션은 위치·시간·주변 3D 형상으로 플랫폼 내부에서 계산한다.

### 2.11 주소·좌표 변환

- **권장 원천:** 도로명주소 검색/좌표 API, 행정구역 코드, 좌표계 변환 모듈
- **수집 방식:** 사용자 문자열을 정제한 뒤 지번·도로명 후보를 제시하고, 법정동코드/본번/부번으로 PNU를 결정
- **산출:** 표준 지번주소, 도로명주소, PNU, 행정코드, WGS84/EPSG:5179 좌표
- **판정:** 전체 파이프라인의 마스터 키를 만드는 필수 계층
- **주의:** 주소 좌표 API의 좌표는 GRS80 UTM-K로 제공될 수 있어 WGS84 변환이 필요하다. [공식 안내](https://m1.juso.go.kr/addrlink/qna/qnaDetail.do?bulletinRefSn=66236)처럼 좌표계 메타데이터를 무시하면 지도 중첩이 어긋난다. 주소 API가 곧바로 완전한 PNU를 반환한다고 가정하지 않는다.

## 5. 통합 데이터 모델

`phase1_result` 하나에 모든 응답을 밀어 넣기보다 다음의 정규 객체를 사용한다.

```ts
type Evidence = {
  provider: string;
  datasetId: string;
  sourceUrl: string;
  observedAt: string;       // 플랫폼 수집 시각
  effectiveAt?: string;     // 데이터 기준일/시행일
  licenseCode: string;
  coordinateSystem?: string;
  rawSnapshotId: string;
  confidence: "verified" | "derived" | "estimated" | "missing";
};

type Fact<T> = {
  value: T | null;
  evidence: Evidence[];
  derivation?: string;      // 계산식 또는 결합 규칙 ID
  warnings: string[];
};

type ParcelIntelligence = {
  identity: ParcelIdentity;
  geometry: ParcelGeometry;
  planning: PlanningConstraint[];
  existing: ExistingBuilding[];
  context: ContextBuilding[];
  market: MarketEvidence;
  demand: DemandProfile;
  climate: ClimateProfile;
  risks: RiskFinding[];
  scenarios: DevelopmentScenario[];
  coverage: CoverageScore;
};
```

핵심은 모든 화면의 숫자를 클릭하면 `어디서 왔고, 언제 기준이며, 원본인지 계산값인지` 확인할 수 있게 하는 것이다.

## 6. API/ETL 아키텍처

### 6.1 데이터 성격에 따른 3개 경로

| 경로 | 대상 | 처리 |
|---|---|---|
| Request-time API | 주소, 건축물대장, 실거래, 기상 등 | timeout/retry/circuit breaker와 캐시를 둔 실시간 호출 |
| Spatial Warehouse | 지적, 용도지역, 건물폴리곤, 도로, 위험지도, DEM | 정기 파일/WFS 적재 → PostGIS/래스터에서 공간질의 |
| Render/Model | 항공 타일, 3D 컨텍스트, 매스 | 화면용 타일과 내보내기용 자체 지오메트리를 분리 |

### 6.2 Connector Registry

각 공급자 코드를 흩어진 `fetch()` 함수로 만들지 말고 레지스트리로 관리한다.

```ts
type ConnectorManifest = {
  id: string;
  datasetId: string;
  protocol: "REST" | "WFS" | "WMS" | "WMTS" | "FILE" | "SDK";
  auth: "serviceKey" | "token" | "none";
  updateCycle: string;
  timeoutMs: number;
  dailyQuota?: number;
  licenseCode: string;
  commercialUse: "allowed" | "restricted" | "review";
  derivativeUse: "allowed" | "restricted" | "review";
  coordinateSystem?: string;
  healthcheck: string;
};
```

### 6.3 저장 계층

1. `raw_snapshots`: API 원문 JSON/XML, WFS 피처, 기준일과 해시를 변경 불가 상태로 저장
2. `normalized_*`: 주소·필지·건물·규제·거래·통계 도메인 테이블
3. `derived_facts`: 경사, 접도, 유사사례 가격, 위험 교차 등 계산 결과와 규칙 버전
4. `analysis_runs`: 한 번의 분석에서 사용한 원천 스냅샷과 계산 버전을 고정
5. `artifact_exports`: PDF/XLSX/GLB/SKP 등 결과물과 생성 조건

### 6.4 실패와 품질

- `Promise.allSettled`는 요청 시 호출하는 동적 API에만 사용한다.
- 필수(PNU/경계), 중요(용도지역/건축물), 보조(기상/POI)를 구분한다.
- 데이터가 없을 때 0으로 저장하지 않는다. `missing`, `not_applicable`, `provider_failed`를 구분한다.
- 분석 상단에 데이터 커버리지와 기준일을 표시한다.
- 공급자 장애 시 마지막 정상 스냅샷을 제공하되 오래된 정도를 명시한다.
- 좌표계는 입수 시 기록하고 내부 표준을 EPSG:5179, 웹 표시를 EPSG:4326/3857로 분리한다.

## 7. 라이선스와 상업화 게이트

공공데이터라는 이유만으로 모든 데이터를 유료 리포트·이미지·3D 파일에 재배포할 수 있는 것은 아니다.

- 데이터셋별로 `상업 이용`, `변경`, `원본 재배포`, `화면 캡처`, `2차 저작물`을 체크한다.
- 예를 들어 일부 홍수지도는 공공누리 제4유형으로 상업 이용·변경이 제한된다. 유료 제품에서는 원본 레이어를 포함시키기보다 공식 페이지로 연결하거나 별도 허가를 검토해야 한다.
- 연속지적도도 API와 대용량 파일의 이용조건이 다를 수 있다.
- 학교·AirKorea 등은 출처표시나 변경 제한이 붙을 수 있다.
- 출시 전에 변호사 검토가 아니라도 최소한 데이터셋별 이용조건 캡처와 승인 기록을 보관하고, 조건이 불명확한 소스는 기능 플래그로 격리한다.

출시 게이트는 다음 네 가지다.

1. 운영계정 승인과 충분한 쿼터
2. 상업 이용 및 2차 산출물 포함 가능 여부
3. 필드별 실제 커버리지/결측률
4. 원천 장애 시 대체 경로와 사용자 표시 방식

## 9. 제품 성공 기준

API 연결 수를 KPI로 삼지 않는다. 다음 지표를 사용한다.

- 주소 입력 후 PNU 확정 성공률
- 필수 데이터 완성률과 평균 기준일
- 자동판정 대비 전문가 확인 필요 비율
- 유사 실거래 표본 수와 가격 추정 오차
- 분석부터 첫 시나리오 표시까지 걸리는 시간
- 사용자가 PDF/3D/공유링크 중 하나를 실제로 내보내는 비율
- 전문가가 결과를 수정한 항목과 수정 폭
- 동일 필지를 재분석했을 때 변경 이유를 설명할 수 있는 비율

판매 가능한 버전의 기준은 "모든 지역의 모든 예외를 안다"가 아니다. **핵심 사실이 안정적으로 모이고, 계산 근거가 보이며, 불확실성을 정직하게 표시하고, 바로 쓸 수 있는 결과물이 생성되는가**다.
